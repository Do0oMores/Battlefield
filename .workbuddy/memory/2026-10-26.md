## 医疗包：一次性回血 → 逐步回血

用户要求：回血包不要再「用完后一次加满」，改成逐步回血。

**改法**（`MedicalPouchService`）：
- 动作截止（14 tick）那一 tick 只做「消耗医疗包 + 登记回血窗口」，**血量不动**。
- 新增 `DRIPS: Map<UUID, Drip(life, end, perTick)>`，每 tick 走
  `PlayerHealthService.healPlayer(min(perTick, 缺口), false)`，`perTick = maxHealth / healTicks`。
  默认 `medicalHealTicks = 40` → 100 血 2.5 血/tick ≈ 50 HP/s，约 2 秒补满。
- 窗口收尾（补满或到期）才 `resetRegenCeiling`（解除动态回血上限）。
- 满血但只缺上限时不起窗口，直接解上限。
- 窗口按 `life` 绑定：死亡/重部署/离局/退出/切维度立即停且**不补上限**；
  `stopped` 清空。窗口期间**不锁动作**（包已经用掉了，可以正常开枪）。
- 每 tick 的普通治疗会把上限抬到当时血量 → 自然回血在窗口内被自身上限挡住，不会两套叠加。

**新增配置**：`medicalHealTicks`（默认 40，1–200），已进 `server_config.json` 的医疗注释串。

**验证**：`./gradlew build` 通过、单测 91 项 0 失败；`runGameTestServer`（`-x downloadAssets -x downloadMCMeta`）
**10 项 GameTest 全过**（"All 10 required tests passed"）。改后的 `serviceDeadlineAndCeilingSettlement` 断言：
tick 13 血量不变 → tick 16 血量已涨但未满 → tick 60 满血且上限已解除。

**注意**：gameTest 不在 `build` 里编译，改 `MedicalConfig` 的 record 参数时要同步
`MedicalGameTests` 里两处 `new MedicalConfig(...)`，否则只有 `runGameTestServer` 才会报错。

## 血条数字去掉 "/100" 后缀

用户要求只显示当前血量数值，不要 `/100`。

- `HealthHudOverlay.healthLabel(float shown)` 抽成独立方法（`Integer.toString(Math.round(shown))`），
  渲染里只调它；取整规则因此可单测（新增 `HealthHudOverlayTest` 3 条：只有数字、整点取整、永不带 `/`）。
- **宽度仍按满血数字预留**（`mc.font.width(Integer.toString(round(maxHealth)))`）：数字从 9→10→100 位数会变，
  按实时宽度排版会让「血条 + 数字 + 医疗十字 + 储备」整组左右抖。实测 100 / 40 / 8 三种位宽下，血条起点与十字位置完全不动。
- 血条填充比例、淡红可恢复段、平滑追赶逻辑都没动。
