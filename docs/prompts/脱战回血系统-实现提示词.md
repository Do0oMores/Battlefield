# 提示词：脱战回血系统（M1 · 100 血基线）

> 用途：直接下发给编码 agent 的实现任务书。
> 版本：v1（2026-10-25）。上游设计结论见 `docs/战地模式-开发结论总纲.md` 与兵种可行性核查。

---

## 0. 一句话目标

让玩家在掩体后 6 秒重新具备再战能力，但**绝不允许在交火中靠回血翻盘**——每一个参数都服务于这一条。

**不可妥协的设计不变式（任何实现方式违反即视为 bug）**：

1. 回血速率 < 交火有效 DPS 的 1/5。否则贴脸对枪可以靠"边打边回"抵消伤害，TTK 失去意义。
2. 回血必须发生在**脱离敌方火力之后**，而不是"停止开火之后"。
3. 数值全部可在运行时改，改完 `/bt reload` 立即生效，不需要重启服务端、不需要重开对局。

## 2. 前置：100 血基线（必须和回血一起做，否则参数没有意义）

当前是原版 20 血。改成 100 血不是换个数，会连带三件事，缺一件就是半成品：

### 2.1 生命上限
- 用 `Attributes.MAX_HEALTH` 的**永久修饰器**做，不要用 `setMaxHealth`（1.20.1 已无此方法），也不要伪造 HUD 数字。
- 固定 UUID 常量，`removeModifier` 后再 `addPermanentModifier`，避免重复叠加。
- 时机：`joinBattle()` 施加；`leaveBattle()` / 结算离场移除并 `setHealth(getMaxHealth())`（回到 20）；`PlayerRespawnEvent` 重新施加并补满（`PlayerList#respawn` 会复制属性，但仍显式重施加一次作为保险）。
- 部署/复活路径已有 `player.setHealth(player.getMaxHealth())`（`PlayerSnapshotStore:98`），改成 100 后自动生效，不要另写补满逻辑。

### 2.2 伤害标定（**这是本次最容易出事故的地方**）
100 血意味着同样的枪要打 5 倍发数才致死。必须提供一个**配置化的子弹伤害倍率**，默认 `1.0`（不擅自改枪械平衡），并在验收里要求实测回填。

- 实现位置：`LivingHurtEvent`，判断 `event.getSource().getDirectEntity() instanceof EntityKineticBullet` 才乘倍率。
- **为什么不能挂在 `EntityHurtByGunEvent` 上**：该事件只有 getter，没有 `setAmount`（已用 javap 核实 1.1.8 的类签名），改不了伤害。
- 为什么用 `getDirectEntity()` 而不是 `getEntity()`：TACZ 子弹是 `EntityKineticBullet extends Projectile`，`getEntity()` 可能是射手，`getDirectEntity()` 才是弹丸本身。
- **副作用必须写进注释**：`ScoreManager` 用血量差算伤害分，倍率会把伤害分同比例放大；若开启倍率，需在 `ScoreManager` 里按同一倍率折回去，或明确接受计分变化。

### 2.3 HUD
- 100 血不能继续用 20 颗心（会变成 50 颗心）。
- 新增 `client/ui/HealthHudOverlay.java`：底部左侧横条 + `87/100` 数字，实血白色、本次可回血上限淡红。
- 在 `RenderGuiOverlayEvent.Pre` 里取消 `VanillaGuiOverlay.PLAYER_HEALTH` 与 `VanillaGuiOverlay.FOOD`；创造/旁观模式不画。
- 只在 `ClientGameState.inBattle` 时绘制。

## 3. 回血模型

### 3.1 状态定义

每名参与者维护：

| 字段 | 含义 |
|---|---|
| `lastDamageTick` | 最后一次**实际受到伤害**的 tick（`level.getGameTime()`） |
| `suppression` | 0..1 的压制值，由支援兵系统写入（本系统只提供接口） |
| `lastRegenTick` | 上次结算回血的 tick，防止同一 tick 重复加 |

**"脱战"的定义 = 距最后一次受到伤害超过 `regenDelayTicks`。开火不算脱战中断**（默认），理由：机枪手持续压制时若不能回血，支援兵会变成自虐兵种。提供 `shootingBreaksRegen`（默认 `false`）作为可选项，开启时才订阅 `GunShootEvent`。

### 3.2 结算规则

每 `regenIntervalTicks` 结算一次：

```
可回血 iff
    phase == RUNNING
 && player.isAlive() && 不是观战者 && 在本局战场世界
 && 出界倒计时未开始（或 regenOutOfArea == true）
 && now - lastDamageTick >= delay + (suppression > 0 ? suppressionDelayBonusTicks : 0)
 && health < maxHealth * regenMaxHealthFraction

heal = regenHealPerInterval * (suppression > 0 ? suppressionRateMultiplier : 1.0)
health = min(health + heal, maxHealth * regenMaxHealthFraction)
```

**不要**用 `MobEffects.REGENERATION`：它按秒加整数点、与饱和/饥饿耦合、无法表达"延迟"和"回血上限百分比"，调不出线性速率。
**不要**每 tick 调 `heal()`：32 人 × 20 tick = 640 次/秒，且每次都会触发客户端血量同步包。

### 3.3 数值（100 血基线，全部标 [PLACEHOLDER]，需实机校准）

| 参数 | 默认 | 换算 | 理由 |
|---|---|---|---|
| `maxHealth` | 100.0 | — | 本次需求基线 |
| `regenDelayTicks` | 120 | 6 s | 100 血下步枪 TTK 约 1.2~2 s，6 s 覆盖"换弹—找掩体—被追"的完整节奏；同时短于据点接触的典型间隔（8~10 s），保证一次交火只有一次回血窗口 |
| `regenIntervalTicks` | 10 | 0.5 s | 视觉连续，且把 `heal()` 压到 2 次/秒/人（32 人 = 64 次/秒） |
| `regenHealPerInterval` | 5.0 | 10 HP/s，满血 10 s | 必须 < 交火有效 DPS 的 1/5；若实测对方 DPS 低于 50，本值要下调 |
| `regenMaxHealthFraction` | 1.0 | 回满 | 留给兵种/压制档位使用，默认不限制 |
| `suppressionRateMultiplier` | 0.25 | 10 → 2.5 HP/s | 压制期间几乎无法自我修复，逼玩家先脱离火力 |
| `suppressionDelayBonusTicks` | 60 | +3 s | 同上，双管齐下 |
| `suppressionDecayPerSecond` | 0.5 | 2 s 衰减 1.0 | 压制是"正在被火力覆盖"的瞬时状态，不是永久 debuff |
| `shootingBreaksRegen` | false | — | 见 3.1 的设计立场 |
| `gunDamageScale` | 1.0 | — | 默认不动枪械平衡，见 2.2 |
| `regenOutOfArea` | false | — | 出界已经判死，回血只是延长痛苦 |

**兵种档位预留（本里程碑不实现，只留接口）**：突击兵 `delay × 0.6 / 速率 × 1.4` → 3.6 s / 14 HP/s，满血 7.1 s。
上表每一个数字都必须能在 JSON 里改，禁止硬编码进 Java。

### 3.4 后台映射（给"可配置"一个准确说法）

- **回血量** = `regenHealPerInterval`（每次结算回多少）
- **回血效率** = `regenHealPerInterval / (regenIntervalTicks / 20.0)` HP/秒
- 改效率有两种改法（拉大单次量 / 缩短间隔），两者对 HUD 的表现不同：拉大量会让血条跳动，缩短间隔更顺滑但同步包更频繁 → 文档里写清楚，默认用"调量"。

## 4. 配置 schema

写进 `config/battlefield/server_config.json` 的根对象，沿用现有 `_comment` 约定（每个字段配一个 `xxx_comment` 字符串），并同时改三处：
`Settings` 字段 + `Settings.from(Root)` + `Root` 默认值。

```json
{
  "combatRegenEnabled": true,
  "combatRegenEnabled_comment": "脱战回血总开关。关闭后完全依赖医疗包/医疗站。",
  "maxHealth": 100.0,
  "maxHealth_comment": "对局内玩家最大生命上限。改这个必须同步校准 gunDamageScale，否则 TTK 会整体走样。",
  "regenDelayTicks": 120,
  "regenDelayTicks_comment": "最后一次受伤到开始回血的间隔（tick，120=6 秒）。",
  "regenIntervalTicks": 10,
  "regenIntervalTicks_comment": "回血结算间隔（tick，10=0.5 秒）。缩短更顺滑，但客户端血量同步包更频繁。",
  "regenHealPerInterval": 5.0,
  "regenHealPerInterval_comment": "每次结算恢复的血量。效率 = 本值 / (间隔/20)，默认 5/0.5s = 10 HP/s。",
  "regenMaxHealthFraction": 1.0,
  "regenMaxHealthFraction_comment": "最多恢复到上限的百分比（0~1）。1.0=回满。",
  "suppressionDelayBonusTicks": 60,
  "suppressionDelayBonusTicks_comment": "被压制时回血延迟额外增加的 tick。",
  "suppressionRateMultiplier": 0.25,
  "suppressionRateMultiplier_comment": "被压制时回血速率的倍率（0~1）。",
  "suppressionDecayPerSecond": 0.5,
  "suppressionDecayPerSecond_comment": "压制值每秒自然衰减量（0~1 范围）。",
  "shootingBreaksRegen": false,
  "shootingBreaksRegen_comment": "自己开火是否重置脱战计时。默认 false：脱战指不再挨打，而不是不再开枪。",
  "gunDamageScale": 1.0,
  "gunDamageScale_comment": "TACZ 子弹伤害倍率，用于对齐 100 血基线。1.0=不改枪械平衡。",
  "regenOutOfArea": false,
  "regenOutOfArea_comment": "离开可活动区域的击杀倒计时期间是否仍可回血。"
```

**校验要求**：
- `regenIntervalTicks`、`regenDelayTicks` 必须 `>= 1`；`regenHealPerInterval`、`maxHealth`、`gunDamageScale` 必须 `> 0`。
- `regenMaxHealthFraction`、`suppressionRateMultiplier` 允许 `0~1`，**不能**用现有的 `positiveDouble()`（它会把 0 判成非法并回退默认值），新增 `fraction(Double, double)` 助手做 `[0,1]` 钳制。
- 解析失败时的行为与现有一致：回退默认值 + `LOGGER.error`，不允许抛异常炸掉 tick。

## 5. 代码落点

新增包 `game/combat/`：

| 文件 | 职责 | 关键点 |
|---|---|---|
| `CombatTracker.java` | per-UUID 的战斗状态表（`lastDamageTick`、`suppression`、`lastRegenTick`） | 内存 `HashMap<UUID, State>`，**不要**落 SavedData；提供 `markDamaged` / `isOutOfCombat` / `applySuppression` / `clear` / `clearAll`；订阅 `LivingHurtEvent` 时优先级取 `LOW`，且必须先判 `event.isCanceled()`（友伤取消是 NORMAL 优先级，LOW 在其后执行） |
| `RegenProfile.java` | record：`delayTicks / intervalTicks / healPerInterval / maxFraction / suppressionRateMult / suppressionDelayBonus` | 由配置构造，不引用 MC 类型 → 可单元测试 |
| `RegenProfileProvider.java` | 函数式接口：`RegenProfile profileFor(ServerPlayer)` | 默认返回基础档；**M2 兵种系统替换实现即可，本系统不改一行** |
| `CombatRegenService.java` | `tick(MatchContext ctx, List<ServerPlayer> participants, long gameTime)` | 配置在 tick 开头取一次快照，循环里只做 long/float 比较；结算用累加器，不依赖 tick 取模（防止 tickCounter 重置丢相位） |
| `PlayerHealthService.java` | MAX_HEALTH 修饰器施加/移除、`EntityKineticBullet` 伤害缩放 | 见 §2.1、§2.2 |

改动点：
- `BattlefieldGameManager.tickMatch()`：`phase == RUNNING` 分支里调用一次 `CombatRegenService.tick(...)`；**复用已经算好的 `participants(ctx)` 列表**，不要在循环里再分配。
- `BattlefieldGameManager.keepPlayerFed()`：目标值 `20` → 常量 `FOOD_TARGET = 17`，并把判断从"低于才写"改成"不等于就写"（防止玩家吃配装里的食物把饥饿顶到 18+ 重新打开原版自然回血），`saturation` 置 0。**这是关闭原版自然回血的开关**，注释里必须写明：原版慢速回血阈值是 `foodLevel >= 18`，快速回血还要 `saturation > 0`。
- `joinBattle` / `leaveBattle` / `onPlayerRespawn` / `onPlayerDeath` / `onLogout`：分别调用 `PlayerHealthService.apply/remove` 与 `CombatTracker.clear`。
- `net/BattlefieldClient.java`：注册 `HealthHudOverlay`（`registerAboveAll`）。
- 客户端新增 `client/ui/HealthHudOverlay.java`，并在 `RenderGuiOverlayEvent.Pre` 取消原版 `PLAYER_HEALTH` 与 `FOOD`。

**明确不做**：
- 不新增任何网络包 → `BattlefieldNet.PROTOCOL` 保持 `"5"`，避免全端重新对齐。
- 不引入 mixin（本项目至今零 mixin，`mixins.json` 的 `mixins` 数组为空，第一个 mixin 在 Mohist 上要单独验证）。
- 不改 `ScoreManager` 的计分口径，除非已按 §2.2 开启 `gunDamageScale != 1.0`，那就在同一个 PR 里把伤害分折回去并写注释。

## 6. 边界与失败态

| 场景 | 期望行为 |
|---|---|
| 死亡 | `CombatTracker.clear(uuid)`；复活时属性重施加 + 满血 + 计时从当前 tick 重新起算（避免"刚复活就回血"或"刚复活还在 6 秒冷却"） |
| 退出对局 / 掉线 | 清 tracker、移除 MAX_HEALTH 修饰器、血量钳回 20 |
| COUNTDOWN / ENDING | 不回血（`phase == RUNNING` 才结算） |
| 观战者 | 不参与（`SPECTATOR` 直接跳过） |
| 出界倒计时中 | 默认不回血 |
| 友伤 | 被 `FriendlyFireHandler` 取消 → 不重置脱战计时（必须在 `isCanceled()` 后跳过） |
| 自伤（摔落/出界/自杀） | **算受伤**，重置脱战计时。理由：摔下去再爬上来不该白送一次满血 |
| 服务器卡顿 / TPS 掉到 10 | 用 `gameTime` 而非墙钟；速率以 tick 计，卡顿不会让回血变快 |
| 配置被改坏（负数/0） | 回退默认值 + 日志，不抛异常 |
| 与 `MobEffects.REGENERATION`（图图腾/药水）共存 | 允许叠加，但本系统不主动加这个效果；若配装里有药水，另行处理 |

## 7. 验收标准（可执行断言）

1. `/attribute <player> minecraft:generic.max_health get` → `100.0`（对局内）；离开对局 → `20.0`。
2. `/data get entity <player> Health` → `100.0f`（满血）。
3. `/damage <player> 40 minecraft:generic` → Health `60.0`；随后每 2 s 采样一次：
   - t=0~5 s：保持 `60.0`（**必须完全不动**，动了说明原版自然回血没关掉）
   - t=6~7 s：出现第一个 +5
   - t≈14 s：`100.0` 满血
4. 改 `regenHealPerInterval` 为 `10.0` → `/bt reload` → 同样的测试，t≈9 s 满血。**进行中的对局也生效**，无需重开。
5. `shootingBreaksRegen=false` 时，边开枪边等待，回血曲线与第 3 条一致。
6. `combatRegenEnabled=false` + `/bt reload` → 受伤后 30 s 内血量不动（**这是"原版自然回血已关闭"的唯一硬证据**）。
7. 死亡 → 部署复活：Health `100.0`，且复活后 6 s 内不回血（计时已重置）。
8. 32 人局 `forge tps`：MSPT 增量 < 0.3 ms（本系统只做 O(P) 比较 + 每人 2 次/秒 `heal()`）。
9. 客户端：不再显示心形与饥饿条；自绘血条数值与 `/data get` 一致。
10. `./gradlew build` 通过；`PROTOCOL` 仍为 `"5"`；服务端与客户端使用同一份 jar。

## 10. 实现者需要主动回报的三件事

1. **实测单发伤害**（TACZ 当前枪包下步枪/冲锋枪/狙击各一发打玩家掉多少血）→ 决定 `gunDamageScale` 该填多少，以及"100 血 + 当前倍率"下的实际 TTK 是多少发。
2. **原版自然回血是否真的关掉了**（第 6 条断言）。这一条不成立，后面所有倍率都是假的。
3. **32 人局的 MSPT 增量**。如果超过 0.3 ms，先查是不是每 tick 都在读配置或每次 `heal()` 都触发了全量属性同步。
