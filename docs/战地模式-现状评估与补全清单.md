# Battlefield 模组 · 现状评估与补全清单

> 评估对象：`D:/code/Battlefield`（Forge 1.20.1 / 47.4.16，TACZ 依赖，Mohist 混合端倾向）
> 代码规模：约 60 个 Java 类 + 3 份 JSON 配置 + 1 份空 ForgeConfigSpec
> 结论口径：以"能否开一场 16v16 的完整突破局"为标准，而非"代码是否跑得起来"

---

## 一、已实现内容（可直接复用的部分）

### 1.1 对局与战线（核心骨架，完成度最高）

| 能力 | 实现位置 |
|---|---|
| 多竞技场（arena）装载 | `config/SectorConfigLoader.java`、`config/battlefield/sectors.json` |
| 多战线（sector）推进 | `game/SectorManager.java`、`breakthrough/Sector.java` |
| 据点占领（-100~+100 进度 / 人数差推进） | `breakthrough/CapturePoint.java`、`SectorManager.updatePoint()` |
| 票数、比赛时长、阶段机 | `game/GameSession.java`、`BattlefieldGameManager.Phase{WAITING,COUNTDOWN,RUNNING,ENDING}` |
| 开局倒计时 / 结算遮罩 / 冻结移动 | `BattlefieldGameManager.tickMatch()`、`client/BattlefieldClientMovementBlocker.java` |

占领推进公式（`SectorManager.java:110-121`）：
`step = captureBaseStep + captureBonusStep × (人数差-1)`，默认 `4 + 2×(diff-1)`。
单人从 -100 推到 +100 需 50 次 tick（`captureIntervalTicks=10` → 25 秒），4 人小队约 10 秒。偏快，但属于可调范围。

### 1.2 队伍 / 小队

- `team/TeamId.java`（ATTACKERS / DEFENDERS / SPECTATOR）
- `team/TeamManager.java`：16v16 自动均衡（少人优先）
- `team/SquadSavedData.java` + `team/SquadManager.java`：4 人小队、每阵营 16 队上限、自动补齐
- 队伍数据用 `SavedData` 落盘，重启不丢

### 1.3 计分

`game/ScoreManager.java` 覆盖 6 类来源，`game/ScoreReason.java` 定义 8 种枚举：

- 伤害：按"每 tick 血量池"封顶（`onLivingHurt` 快照 + `onLivingDamage` 扣减），避免多段伤害重复计分 —— 这块设计是对的
- 击杀 100 / 爆头 +25 / 连杀 +50 / 小队团灭 +200 / 占点与防守每 3 秒 +5
- Toast 合并（6 tick 窗口）+ 12 tick 后强制 flush，走 `S2CScoreToastPacket`

### 1.4 HUD 与可视化

- `client/ui/BattlefieldHudOverlay.java`：顶部计时+票数、菱形据点环（扇形填充表示争夺进度）、小队分数、中央得分飘字、阶段遮罩、出界警告
- `client/BattlefieldAreaRenderer.java`：地面圈 + 可活动区域白框（world-space 线框）
- `client/ClientGameState.java`：客户端状态镜像 + 语音触发

菱形按"蓝永远代表我方"渲染（`blueFrac` 随 `myTeam` 翻转），这个细节做得比多数同类模组好。

### 1.5 区域规则

- `config/BattlefieldServerConfig.java`：34 项热重载参数（`/bt reload`）
- `BattlefieldGameManager.enforceMovableArea()`：出界 200 tick 后强制击杀
- `game/BattlefieldAreaRules.java`：矩形 2D 判定

### 1.6 补给与火力支援

- `block/TaczAmmoStationBlock.java`：TACZ 携弹上限补给，15 秒冷却，同时兼容"背包弹药"和"虚拟弹药（dummy ammo）"两种枪械模式
- `server/BombardmentManager.java` + `server/entity/BombEntity.java` + `server/explosion/BombEffects.java`：区域轰炸，逐玩家发红/蓝烟（敌我视角区分）
- `game/V1StrikeManager.java` + `server/entity/V1MissileEntity.java`：贝塞尔弹道、20 格即死 / 30 格平方衰减、可被方块拦截

### 1.7 复活 / 部署 / 背包

- `server/entity/RespawnBeaconEntity.java` + `game/RespawnBeaconManager.java` + `block/RespawnBeaconItem.java`：小队复活信标（可放置、可摧毁、40 血）
- `client/ui/RespawnDeployScreen.java`：U 键打开，背包槽 1-9 切换 + 7 格物品预览
- `server/BackpackBridge.java`：反射调用 Bukkit 侧 `Backpack` 插件，套用配装预设

### 1.8 其它

- `team/FriendlyFireHandler.java`：友伤拦截
- `BattlefieldGameManager.syncNameTagTeams()`：同队名牌可见、异队隐藏（`HIDE_FOR_OTHER_TEAMS`）
- `client/VoiceManager.java` + `assets/battlefield/sounds.json`：8 条战地风格语音
- `command/BtCommands.java`：`/bt join|leave|reload|testBombard|testV1`

## 二、缺失项

### 2.1 兵种与装备体系（完全空白）

全项目 **0 行** 兵种代码。当前逻辑是"谁都能拿任何枪、任何配件"，`/bt join` 之后没有任何配装约束。

缺失内容：
- 兵种定义（突击 / 医疗 / 支援 / 侦察 / 工程）
- 每兵种的武器池、配件池、携弹量、移动速度/护甲修正
- 兵种专属装备：医疗包、弹药包、修理工具、侦察标记、C4/反坦克雷
- 兵种选择界面与"死亡后可换兵种"流程
- 兵种人数上限（防止全队狙击）

> 现有 `block/MedicalSupplyBlock.java` 是一个 **空类**（只有构造函数），且 **未注册** 到 `block/ModBlocks.java`，但 `assets/battlefield/` 下 blockstate / model / texture / lang 全都做了。这是一个明确的半成品，可作为医疗兵装备的起点。

### 2.2 武器与配件配置（完全空白）

- **无枪械白名单**：没有 TACZ gun id 的准入表，创造模式能掏出任何枪，管理员无法禁用 OP 武器
- **无配件准入**：TACZ 的 scope / muzzle / grip / stock / laser 没有任何服务端校验
- **无服务端权威校验**：TACZ 默认由客户端上报配件组合，服务端缺少"该兵种是否允许该配件"的复核 → 改客户端即可装高倍镜+消音器
- **携弹表为空**：`config/battlefield/tacz_ammo_caps.json` 是 **0 字节文件**；`TaczAmmoCapConfig.getOrCreate()` 首次遇到某把枪就用 `magSize × 3` 现算并**立刻写盘**（`TaczAmmoCapConfig.java:60-76`），等于每次部署新枪种都会触发一次阻塞 IO
- **无枪械属性覆写**：伤害 / 射速 / 后坐力 / 弹速全部沿用 TACZ 原始值，没有按战地节奏做整体缩放

### 2.3 载具（完全空白）

坦克、装甲车、直升机、快艇、防空，一行都没有。这是战地与"枪战服"最大的体感差异。可选路线：

1. 轻量：`Immersive Vehicles` / `Valkyrien Skies` 接入 + 自定义出生点与载具限制
2. 中量：自研"载具实体 + 座位 + 血量 + 爆炸"，复用现有 `BombEntity` 的伤害管线
3. 重量：对接 `Superb Warfare` 等现成载具模组，只做刷新点与队伍归属

### 2.4 地图与据点玩法

- **只有突破（Breakthrough）**，没有征服（Conquest）—— 后者才是战地主模式
- 据点只支持 **圆形 + 2D 判定**，没有高度区间。多层建筑里"楼顶和地下室同属一个点"
- 区域只有 **矩形**，没有多边形/圆柱/自定义形状
- 无地图元数据：缩略图、地图名、边界、锁定时间/天气、禁用方块破坏规则
- 无"部署点选择"：`spawnIndex` 在客户端恒为 0（`RespawnDeployScreen.java:21`），服务端直接忽略
- 无出生点保护 / 无 spawn camp 抑制
- 无据点内"占领中"的客户端音效与进度提示音

### 2.5 结算与战绩

- 无 K/D/A 统计（只累计总分）
- 无 kill feed（谁杀了谁、用什么武器、是否爆头）
- 无 sidebar 计分板（只有自绘 HUD）
- 无赛后结算表（只有 10 秒遮罩 + `winCommand`）
- 无 MVP / 最佳小队

### 2.6 玩家平衡性机制

- 无中途加入的强弱平衡（只按人数，不按分数）
- 无 AFK 检测与踢出
- 无自动换边 / 战局重排
- 无出生保护（无敌帧）
- 无"防守方票数"（`GameSession.defenderTickets` 从不赋值，恒为 0）
- 无观战模式（满员返回 `SPECTATOR` 但玩家留在原地、不切 gamemode）

### 2.7 工程与运维

- 无比赛状态持久化：服务器重启后 `MATCHES` / `PLAYER_MATCH` 全清空，玩家变成"在场但不在局"的幽灵
- 无断线重连保护期（断线即 `leaveBattle`，分数与队伍清空）
- 无管理命令：`/bt team set`、`/bt kick`、`/bt forcestart`、`/bt pause` 全缺
- 无 `README` / 配置字段说明文档（`_comment` 字段做得不错，但只覆盖 `server_config.json`）

## 三、潜在问题（按严重度分组）

### P0 — 会导致玩法失效 / 数据丢失 / 客户端断连

**① 部署请求把玩家送到世界出生点**

`net/C2SDeployRequest.java:40-41`
```java
var pos = level.getSharedSpawnPos(); // 世界出生点
sp.teleportTo(level, pos.getX() + 0.5, pos.getY() + 1.0, pos.getZ() + 0.5, ...);
```
- `spawnIndex` 完全未使用，`bpSlot` 只做 1-9 范围检查
- 结果：点 DEPLOY 后玩家被丢到 `world spawn`，而不是队伍出生点 / 复活信标
- 副作用：任何玩家（含非对局玩家）都能发包实现"免费回城传送"

**② 队伍/小队数据按维度存储，跨维度即丢失**

`team/TeamManager.java:15-18`、`team/SquadManager.java:23-27` 都使用 `p.serverLevel()` 取 `SavedData`，而 `SavedData` 是 **维度级** 的。
只要 `wait` / `lobby` / `firstAttackSpawnPoint` 位于不同维度，玩家一切换世界就变成 SPECTATOR、小队归零。
修复：统一固定到 `ServerLevel.OVERWORLD`。

**③ `sectors.json` 里的世界 ID 不成立**

`src/main/resources/config/battlefield/sectors.json` 全部写的是 `"world": "minecraft:world"`。
1.20.1 主世界维度键是 `minecraft:overworld`，`minecraft:world` 在 `ServerLevel.getLevel()` 查不到 → `SectorConfigLoader.resolveLevel()` 静默回退到默认世界。
更危险的是 `server/MohistTeleport.java`：它把 `world` 当 **Bukkit 世界名** 用，`normalizeWorldName("minecraft:the_nether")` 得到 `"the_nether"`，而 Mohist 里下界叫 `"world_nether"` → `Bukkit.getWorld()` 返回 null → 走 `createWorld(new WorldCreator("the_nether"))`，**凭空生成一个同名空世界**。
同一个字段被两套解析器用两种语义消费，必须统一。

**④ 背包与游戏模式不恢复，装备永久丢失**

`BattlefieldGameManager.startEnding()` 直接 `sp.getInventory().clearContent()`，`finishAndReset()` 只把玩家传回 lobby，**没有赛前背包快照、没有恢复、没有还原 gamemode**。
`/bt join` 时也没有快照或清空。玩家带进场的装备会被吞掉，且清空范围只覆盖主背包（不含盔甲/副手）。

**⑤ 多局并行时计分互相清空**

`BattlefieldGameManager.resetMatch()` 调用的是全局 `ScoreManager.reset()`（`ScoreManager.java:63-75` 清全部 Map）。
`MATCHES` 明明支持多 arena，但只要有一局结束，所有局所有人的分数一起归零。`SquadSavedData` 同样只按维度分、不按 arena 分。

**⑥ 状态包字符串长度不匹配，会踢人**

`net/S2CGameStatePacket.java:92` 编码用 `buf.writeUtf(p.id)`（默认 32767 上限），`:130` 解码用 `buf.readUtf(8)`。
配置里 `id` 写成 `"POINT_ALPHA"`（11 字符）就会在客户端解码时抛异常 → 断连。同理 `squadPlayerIds` 编码不限长、解码 `readUtf(32)`。

**⑦ 复活信标"能放不能用"**

`game/BeaconRespawnLogic.java` 全项目 **无任何调用点**（已用 grep 确认），是死代码。
`onPlayerRespawn()` 无条件把玩家送回 `firstAttackSpawnPoint` / `firstDefendSpawnPoint`，信标系统完全没接入重生流程。

### P1 — 影响体验与公平性

**⑧ 每 tick 全量同步，性能天花板很低**

`tickMatch()` 末尾无条件 `sendState(ctx)`（`BattlefieldGameManager.java:332`），对 **每个参与者** 发 **完整包**（含所有据点 + 小队名单 + 分数）。
32 人局 = 640 包/秒，每包都在重建 `buildPoints()`（`:576`，每人重算一次，而非一次建好复用）。
应改为：状态脏标记 + 2~5 tick 一次；据点/小队数据只在变化时发。

**⑨ 每 tick 全量写记分板**

`syncNameTagTeams()`（`:344`）每 tick 对每个参与者执行 `scoreboard.addPlayerToTeam()` + 两轮 `pruneTeamMembers()`（各建一个 `HashSet`）。
32 人 = 每秒 640 次记分板写入。只在队伍变化时执行即可。

**⑩ 出界检测遍历全服玩家**

`enforceMovableArea()`（`:701-740`）遍历 `getPlayerList().getPlayers()` 全服玩家，再逐个 `ctx.participants.contains()` 过滤。
多局并行时是 `O(局数 × 全服人数)` / tick。直接遍历 `ctx.participants` 即可。

**⑪ 计分时间基准混用**

`ScoreManager.addScore()` 用 `player.serverLevel().getGameTime()`，而 flush 循环（`:316-351`）用 `server.getTickCount()`。
两个计数器在正常情况下同步，但维度未 tick、`/time` 操作、Mohist 异步区块等场景会漂移 → toast 要么立刻喷出、要么永不刷新。同理 `GameSession.getRemainingTicks()` 也依赖 `level.getGameTime()`。

**⑫ 友伤拦截可能不生效，且可能与计分抢跑**

`FriendlyFireHandler` 和 `ScoreManager.onLivingHurt` 都挂在 `FORGE` 总线的 `LivingHurtEvent` 上，**没有指定 `EventPriority`**，执行顺序不确定。
更关键的是 TACZ 枪械伤害走自家 `EntityHurtByGunEvent` 管线，取消 `LivingHurtEvent` 未必能拦住最终的 `hurt()` 结算。实测前不要假设友伤已经安全。

**⑬ 最后一点判定逻辑自相矛盾**

`isSpecialLastPointCapturing()`（`:493-508`）先判断"最后一点进度已满"（此时 sector 早该 cleared），再要求"该 sector 所有点都不属于守方"才返回 true —— 与"正在被占领"的语义相反。这会让"票数耗尽但最后一点正在被攻方拿下"这个战地经典瞬间判定错误。

**⑭ 配置错误会导致开局秒结束**

`SectorConfigLoader.parseSectors()` 会丢弃 `points` 为空的 sector。若某 arena 所有 sector 都被丢弃，`currentSector()` 返回 null → `checkWinConditionBySector()` 立刻判攻方胜。
**加载期必须校验**：`sectors.size() > 0`、每 sector `points.size() > 0`、区域矩形与据点是否相交、出生点是否在区域内。

**⑮ 结算命令刷屏**

`executeResultCommands()`（`:591-604`）对每个参与者各执行一遍 `winCommand`，`"say {player} 胜利"` 会被执行 16 次。
应支持 `{player}`（逐人）与 `{arena}` / `{winner}`（单次）两种模式。

**⑯ 配置文件打包位置无效**

`src/main/resources/config/battlefield/*` 下的 `sectors.json` / `tacz_ammo_caps.json` / `license.json` / `lang/*.json` **不会被 Forge 复制到实例的 `config/` 目录**。
运行时读的是 `<实例>/config/battlefield/sectors.json`，文件不存在就由 `writeDefault()` 生成一份占位地图（单 arena、单 sector、单点 A）。
如果当前是"改 resources 里的 json 却看不到效果"，原因就在这里。需确认实际部署方式（手动拷贝 / 打包脚本 / 首次生成后编辑）。

**⑰ 纯 Forge 端的功能降级与硬依赖**

- `build.gradle:91` 引入 `spigot-api`（compileOnly），`server/MohistTeleport.java` 直接 `import org.bukkit.*`
- `server/BackpackBridge.java` 硬编码插件名 `"Backpack"` 与类 `top.mores.backpack.GUI.SingleBackpack`
- `mods.toml` 只声明了 forge / minecraft / tacz 三个依赖，**没有声明需要 Mohist/Arclight**
→ 纯 Forge 服上，跨世界传送与配装预设会静默失效，且 `mods.toml` 不会给出任何提示。

**⑱ 据点缺高度判定**

`SectorManager.updatePoint()` 只算 `dx²+dz²`。地下室蹲点可以占楼顶的点，反之亦然。建议给 `PointJson` 加 `yRange` 或 `height`。

**⑲ 观战未落地**

`joinBattle()` 满员时 `return TeamId.SPECTATOR`，但玩家既没切 `GameType.SPECTATOR`，也没被传送，留在原地还能开枪。

**⑳ 区域判定有两套并行实现**

`BattlefieldAreaRules.isInsideMovableAreaServer()`（圆形，基于 `areaRadiusScale`）**无任何调用点**；
实际生效的是 `isInsideAreas2D()`（矩形）。`areaRadiusScale` 这个配置项因此是"死配置"，会让调参的人困惑。

## 四、优先级建议

### 第 0 阶段 · 先让它"不出错"（1~2 天）

| 优先级 | 事项 | 涉及文件 |
|---|---|---|
