## 一、项目速览

| 项 | 值 |
|---|---|
| 定位 | Minecraft 1.20.1 Forge 模组，实现"战地"式突破玩法（攻守 + 据点 + 票数） |
| 技术栈 | Forge 47.4.16 / Java 17 / TACZ 1.1.8 依赖 / 运行于 **Mohist**（Forge + Bukkit 混合端） |
| 包根 | `top.mores.battlefield` |
| 入口 | `Battlefield.java`（mod 主类）、`game/BattlefieldGameManager.java`（对局总控，~900 行） |
| 核心包 | `game/`（对局）、`team/`（阵营与小队）、`breakthrough/`（战线与据点）、`net/`（网络包）、`client/`（HUD 与渲染）、`server/`（轰炸、传送、背包桥） |
| 配置 | `config/battlefield/sectors.json`（竞技场/战线/据点）、`server_config.json`（热重载参数，字段自带 `_comment` 说明）、`tacz_ammo_caps.json` |

**对局状态机**：`WAITING → COUNTDOWN → RUNNING → ENDING → (reset)`
**核心数据流**：`SectorManager.tick()` 算据点进度 → `BattlefieldGameManager.sendState()` 广播 `S2CGameStatePacket` → `BattlefieldHudOverlay` 渲染。

## 二、架构上已经正确的部分（不要重复改）

| 机制 | 为什么是对的 |
|---|---|
| 维度级广播 | `BattlefieldNet.sendToAllInLevel()` 用 `PacketDistributor.DIMENSION`，天然实例隔离 |

## 三、三轮修改清单

### 第一轮：性能（每 tick 全量类缺陷）

| 位置 | 原问题 | 改法 |
|---|---|---|
| `BattlefieldGameManager.sendState()` | 票数/据点/阶段文案在逐玩家循环里重算；小队快照每人重做 O(P) 扫描 + `Comparator.comparing(UUID::toString)` 排序 | 构建一次广播多人；快照按 `(阵营,小队号)` 缓存；比较器换 `getScoreboardName` |
| `tickMatch()` 尾部 | 状态包 + 名牌队伍每 tick 无条件执行 | 新增 `syncPeriodicViews()`：状态包 20Hz→10Hz、名牌 20Hz→1Hz，阶段切换强制补发（`MatchContext.lastSyncedPhase`） |
| `enforceFrozenPhaseMovement()` | 每 tick 对每人 `teleportTo` 回拉（640 次/秒） | 仅当漂移 >0.5 格才回拉 |
| `enforceMovableArea()` | 遍历**全服**玩家再 `participants.contains` 过滤 | 只遍历本局参与者；新增 `participants(ctx)` 助手 |
| `ensureNameTagTeam()` / `pruneTeamMembers()` | 每 tick 重写 3 个队伍属性 + 构造 HashSet 副本 | 属性只在创建时写；无变化提前返回 |
| `SectorManager` | 每个据点都重取一次在线玩家列表 | tick 级取一次，`updatePoint()` 加参数 |
| `TaczAmmoCapConfig.getOrCreate()` | 遇到新枪种就**同步重写整份 JSON**（主线程 IO） | `dirty` 标记 + `flushIfDirty()`，由 `AmmoStationCooldownCleaner`（100 tick，仅主世界）落盘；`onServerStopped` 补刷 |

### 第二轮：烟幕与 V1 尾迹

| 位置 | 原问题 | 改法 |
|---|---|---|
| `S2CBombardSmokePacket` | 每玩家一个包（颜色不同），32 人局 15 秒轰炸 ≈ 8000 包 | 去掉 `r/g/b`，改带 `ownerTeam` 1 字节；客户端用 `ClientGameState.myTeam == ownerTeam` 判红蓝 |
| `BombardmentManager.sendSmokePerViewer()` | 遍历全服玩家逐人发包，不判距离 | 一次 `PacketDistributor.NEAR` 广播（96 格）；加坐标有限性 / `getServer()==null` / `players().isEmpty()` 三道前置判断 |
| `V1MissileEntity.spawnTrail()` | 每 tick 3 采样点 × 2 种粒子 = 6 次广播，每次内部 O(P) 扫描 | 2 tick 间隔、3 点合 1 中点、先筛 64 格观察者、用逐人重载 `sendParticles(viewer,...,true,...)` |
| `BattlefieldNet.PROTOCOL` | — | `"1"` → `"2"`（烟幕包体布局已变） |

> 关键 API 事实：`ServerLevel` 的逐人粒子方法是 **`sendParticles(ServerPlayer, T, boolean, ...)`**（同名重载），不是 `sendParticle`；`force=true` 时内部距离阈值是 **512 格**。
> `PacketDistributor.TargetPoint` 第 4 个参数是 **半径本身**（内部才平方），不是半径平方。

### 第三轮：七项系统性问题

| # | 位置 | 根因 | 修法 |
|---|---|---|---|
| 1 | `net/C2SDeployRequest` | 写死 `getSharedSpawnPos()`，`spawnIndex` 未使用；无任何校验，人人可发包白嫖传送 | 包只传索引；`BattlefieldGameManager.deploy()` 全量校验（对局归属/阶段/阵营/存活/索引范围）；阵亡时记 `PENDING_SPAWN_INDEX`，复活瞬间二次解析 |
| 2 | `team/TeamSavedData`、`SquadSavedData`、`TeamManager.countTeam` | `SavedData` 按维度分桶，`get(p.serverLevel())` 导致跨维度丢队伍 | `get()` 内部锚定 `server.overworld()`（调用点零改动）；`countTeam` 去掉 `sp.serverLevel()==level` 过滤 |
| 3 | `config/SectorConfigLoader`、`server/MohistTeleport`、`BattlefieldGameManager.teleportTo` | 配置写 `minecraft:world`（非法维度键）；`MohistTeleport` 拿维度 ID 当 Bukkit 名，找不到就 `createWorld` 建空世界 | 配置与 `writeDefault()` 改 `minecraft:overworld`；`resolveWorld()` 改为「原版别名 → `World#getKey()` → 仅裸名才 createWorld」；`teleportTo()` 改 NMS → Bukkit → 告警取消（不再静默退 fallback） |
| 4 | 新增 `game/PlayerSnapshotStore` | `startEnding()` 清背包，`finishAndReset()` 不还原 | SavedData（锚主世界）存 inventory/selected/gamemode；`joinBattle` capture、`leaveBattle`/`finishAndReset` restore、`onLoggedIn` 补发残留快照 |
| 5 | `BattlefieldGameManager.resetMatch()` | 调全局 `ScoreManager.reset()`，一局结束全场清分 | 删掉该调用，只保留 `participants.forEach(clearPlayer)`（已覆盖 11 张表） |
| 6 | `net/S2CGameStatePacket` | 编码 `writeUtf(id)` 不限长、解码 `readUtf(8)`，超长即断连 | 常量 `MAX_POINT_ID_LENGTH=8` 两端共用 + `clamp`；`overlayTitle/Sub` 统一 128/512；`SectorConfigLoader` 加载期拒绝超长 id 并打 ERROR |
| 7 | `game/BeaconRespawnLogic` | 逻辑完整但**零调用点**，`onPlayerRespawn` 硬编码回主出生点 | `onPlayerRespawn` 三级优先：显式选择 → `tryAutoRespawn`（按距离排序逐个试）→ 主出生点；`BeaconSpawnCandidate` 增加 `ServerLevel` 字段 |

**协议兼容性**：第 3、4、5、6、7 项均未改变任何包的字节布局，**不需要再升协议号**；只有第二轮升到了 `"2"`。

## 四、Mohist 行为的关键实证（不要再猜）

来自 `forge tps` 与存档目录检查：

1. **Mohist 把 Bukkit 世界注册成 `minecraft:<世界名>`**
   实测维度列表：`minecraft:overworld`、`minecraft:the_end`、`minecraft:world2`、`minecraft:lobby`。
   → 主世界的键永远是 `minecraft:overworld`（文件夹叫 `world`），**`minecraft:world` 不是合法维度**。
   → `World#getKey()` 是跨命名策略的可靠兜底。

2. **`Bukkit.createWorld()` 在 Mohist 上确实会成功**
   这正是危险点：不抛异常、静默注册新世界、写入世界列表、之后每次开服都加载；
   `WorldCreator` 默认 environment 是 NORMAL，造出来的 `the_nether` 是普通世界而非下界；
   且在主线程生成出生区块，会卡 tick。

3. **旧版本的维度级存储确有发生**
   `lobby/data/battlefield_teams.dat`（2026-02-28）与 `world/data/battlefield_teams.dat`（新版）并存。

4. **`online-mode=false` 必须配 `enforce-secure-profile=false`**
   否则离线客户端卡在 `Connecting to …`，服务端 18 秒后 `lost connection`，两端都不报原因。

5. **SavedData 文件外层有 `data` + `DataVersion` 包裹**
   读业务字段要先取 `["data"]`。

6. **关服会消费背包快照**
   `stop` → 踢人 → `PlayerLoggedOutEvent` → `leaveBattle` → `restore`。
   → "中途重启不丢装备"成立。

## 六、遗留问题（按优先级）

### P0（玩法不通）
- **兵种体系 0 行代码**（回血底盘已落地：100 血基线 + 脱战回血 + `RegenProfileProvider` 注入点，见第九节）；
  `block/MedicalSupplyBlock` 是空类且未注册到 `ModBlocks`
- **武器/配件零准入**：无枪械白名单、无配件服务端复核；`tacz_ammo_caps.json` 初始为空，靠 `magSize×3` 现算
- **载具 0 行**

### P1（体验/公平）
- 无 K/D/A、无 kill feed、无 sidebar、无赛后结算表
- 无出生保护、无 AFK 处理、无自动换边
- 观战未落地（满员返回 SPECTATOR 但玩家留在原地、不切 gamemode）
- 据点只有 2D 判定，无高度区间（楼顶与地下室算同一个点）
- `RespawnBeaconManager.getSquadBeacons()` 仍是 ±3000 万 AABB 全图扫描，现在每次复活都会走一次

### P2（工程）
- `Config.java` 是空 `ForgeConfigSpec` 但仍注册 → 生成一份空 toml，与两份 JSON 三轨并行
- `Battlefield.java` 留有 `System.out.println` 调试输出与非静态内部订阅类 `ModBusDebug`
- `src/main/resources/config/battlefield/*` 不会被 Forge 复制到实例 `config/`，运行时读的是实例目录那份
- `lang/zh_cn.json` 缺 `key.battlefield.open_respawn_ui`、`item/entity` 名称

### 已知取舍
- 死亡掉落物 + 结算还原构成理论复制路径 → **建议战场世界开 `keepInventory`**
- `PlayerSnapshotStore` 依赖 SavedData 自动保存，进程被强杀仍可能丢快照
- 部署界面客户端仍固定发 `spawnIndex=0`，索引 1..N 目前只能靠手改包触发
- V1 尾迹从"3 点细线"变成"单点团雾"，`TRAIL_INTERVAL_TICKS` 可回退为 1

## 九、脱战回血与 100 血基线（2026-10-25 已落地）

兵种系统（M2）的前置条件补齐。完整断言与采样见 `docs/战地模式-实测记录-脱战回血.md`。

**做了什么**
- 100 血是真的改 `Attributes.MAX_HEALTH`（固定 UUID 的永久修饰器，进局挂、离局摘），不是 HUD 换算。
- 脱战回血：距**最后一次实际受伤** 6 秒后开始，**每 0.1 秒 +1 点**（10 HP/s，`regenIntervalTicks=2`），
  用 `setHealth` 结算，不用 `MobEffects.REGENERATION`（表达不了延迟与上限百分比），也不每 tick `heal()`。
  粒度是刻意的：`10 tick × 5 血` 与 `2 tick × 1 血` 效率一样，但前者在 HUD 上是整段跳、
  后者才是逐点上涨。**改粒度不用动逻辑，只改这两个数**。
- 受伤即中断：不是额外开关，`lastDamageTick` 一更新，下一次结算的延迟判定就过不了；
  恢复后仍从 +1 开始，不会把停顿期间的血补回来。
- 原版自然回血靠 `keepPlayerFed` 喂 **17** 关掉（原版门槛 18，快速回血还要 `saturation>0`），
  且改成「不等于就写」——否则玩家吃口食物就把原版回血重新打开。
- 配置 12 个参数全部进 `server_config.json`，`/bt reload` 对**进行中的对局**立即生效（实测成立）。
- 客户端 `HealthHudOverlay`：白实血 + 淡红「可回血段」+ `87/100`，取消原版心形与饥饿条。
  **位置在经验条正上方**（原版心形那一行，居中），不放最左下角 —— 那里会被聊天栏整片盖住。
  显示值再做一层非对称平滑：涨的时候按帧追（连续爬升），掉血当帧对齐（不许慢慢淌）。

**没做（刻意的）**
- 不加任何网络包 → `PROTOCOL` 仍是 `"5"`；不引入 mixin。
- `gunDamageScale` 默认 `1.0`，不擅自改枪械平衡；**实测单发伤害后需要回填**，否则 100 血下 TTK 是原来的 5 倍。

**代码落点**
`game/combat/`：`CombatTracker`（纯逻辑，可单测）/ `RegenProfile` / `RegenProfileProvider`（M2 兵种注入点）/
`CombatRegenService`（结算 + `LivingHurtEvent`/`GunShootEvent` 监听）/ `PlayerHealthService`（属性修饰器 + 子弹倍率）；
`config/CombatConfig`（12 参数校验与 `[0,1]` 钳制）；`client/ui/HealthHudOverlay`。

**M2 接入方式**：`CombatRegenService.setProfileProvider(player -> ...)` 返回
`RegenProfile.BASE.scaled(延迟倍率, 速率倍率)` 即可，结算逻辑一行都不用改。

## 十、动态回血上限（2026-10-26 已落地）

战地式的「伤情」：**自然回血只能补回一部分伤害，剩下的是永久伤，必须靠医疗包**。
完整报告见 `docs/战地模式-动态回血上限-开发与实测报告.md`。

**规则**
- 受伤时 `ceiling -= (实际损失 - min(实际损失, maxRecoverableDamage))`，且**只能降不能升**。
  `maxRecoverableDamage` 默认 30（100 血标尺），所以挨 60 只能回到 70、挨 15 能回满。
- 上限存在 `CombatTracker.State.regenCeiling`（和脱战计时同一份内存状态）：
  死亡清、复活重置、离局清、切维度保留。不落盘。
- `CombatRegenService.tick` 只改一行：`cap = min(档位上限, regenCeiling)`。脱战判定、6 秒、0.1 秒 1 点全都没动。

**⚠️ 与最初设计稿的偏差**：设计稿写的是 `min(旧上限, 新血量 + 可恢复量)`，
在「满血挨打」时与现在的实现完全等价；但玩家**正在回血途中**再挨一下时，那个式子会把还没回上来的血
算成永久伤（上限 70、血量 40 挨 1 点 → 上限掉到 40）。实现里改取
`min(旧上限, max(旧上限 − 永久伤, 新血量 + 可恢复量))`，两种情况下都自洽。

**治疗入口**：`PlayerHealthService.healPlayer(player, amount, resetRegenCeiling)`。
死亡玩家直接返回 false；治疗不会超过最大生命值；`reset=true`（医疗包/管理员）把上限还给玩家，
`reset=false` 只保证上限不低于治疗后的血量。医疗包物品还没做，接入时调这一个方法即可。

**测试指令**（`/bt` 与 `/battlefield` 是同一棵树，后者是 redirect 别名，不是第二份注册）：
- `/battlefield heal [player]` —— 满血 + 重置上限（`hasPermission(2)`）
- `/battlefield regeninfo [player]` —— 生命 / 最大生命 / 当前自然回血上限

**已知缺口**：客户端血条的淡红「可回血段」还按 `regenMaxHealthFraction` 画，不反映 ceiling，
挨 60 之后血条会显示 40→100 的淡红而实际只回到 70。要修必须发新包（`PROTOCOL` 5→6），本轮范围外。
