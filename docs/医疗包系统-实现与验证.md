## 2. 储备与重连

权威储备位于现有 `TeamSavedData`（主世界 `data/battlefield_teams.dat`）的 `medical` 玩家记录中，保存角色、储备 0/1、部署生命 UUID、战局和队伍。医疗兵用角色能力表达无限，库存保持 0，不使用哨兵库存值。动作、装备快照和投递冷却仅为临时数据。

原仓库登出会离局并还原背包，无法维持同一次生命。本次改为：同一服务器、同一仍有效战局内，登出保留成员资格、赛中装备和部署记录；取消医疗、销毁相关投递，不重置储备或回血上限。重连读取同一 SavedData，不重新发包储备。离线成员继续占用战局名额，战局时限照常推进。

战局结束或服务器重启后不恢复旧战局；登录沿用已有赛前快照还原。正常存档持久化储备；崩服不会复活旧医疗动作，服务器启动清理医疗部署记录，与原有战局不跨重启的规则一致。

## 3. 部署与生命周期

正式进入开局出生点、中途加入出生点、倒计时中的有效部署确认、死亡后的部署/既有安全回落出生点，才初始化新生命：普通兵种 1，医疗兵无限能力。部署界面点击兵种仅改变本地候选，随有效部署请求提交；拒绝部署不会变更角色或储备。未明确选择时首次部署为突击兵。

死亡、换队、离局、重新部署会取消动作并使旧生命失效。退出与切维度立即取消动作、销毁相关投递；切维度本身不补库存。仅 RUNNING 阶段、处于本局世界、已部署、存活、非旁观且无等待部署/待处理重生的玩家可使用或接收。实际仓库没有倒地状态；不臆造外部倒地 API，未来引入该系统应在同一资格入口接入失效处理。

## 4. 自疗时间线与结算

默认从服务端接受意图的 tick 起计 14 tick。前 13 tick 不进行任何治疗；第 14 tick 的 ServerTick END / LOWEST，位于世界伤害及现有自然回血之后，复核当前动作对象、动作标识、部署生命、资格、角色、库存、装备和治疗需求。一次结算后立即清动作，无法重放。

生命未满或动态回血上限仍受限才允许开始。满血且无上限限制拒绝；结算前已被其他来源完整治疗时结束动作而不扣包。

**结算不再一次性加满血，而是起一段逐步回血窗口**（`medicalHealTicks`，默认 40 tick）：

- 结算那一 tick 只做「消耗医疗包 + 登记回血窗口」，血量不动；
- 随后每 tick 用 `PlayerHealthService.healPlayer(step, false)` 补 `maxHealth / healTicks` 点（100 血 / 40 tick = 2.5 血每 tick ≈ 50 HP/s），补满或窗口结束即停；
- 窗口收尾时调用 `CombatRegenService.resetRegenCeiling`，解除动态回血上限；不改最大生命、不授予吸收或无敌、不伪造最后受伤时间；
- 满血但上限受限时没有血量可补，直接解除上限，不起窗口；
- 普通库存 1→0 在结算那一 tick 就完成，与回血进度无关；医疗兵不消耗。

逐步回血期间**不锁动作**：医疗包已经用掉了，玩家可以正常开枪。窗口按 `life` 绑定当前生命，死亡、重新部署、离局、退出、切维度都会立即终止且不补上限。每 tick 走的是「普通治疗」，它会把回血上限抬到当时血量，因此自然回血在窗口内不会插一脚（`health >= cap`），不会出现两套回血叠加。


装备检查同时比较快捷栏选槽、主/副手实际栈身份、物品类型、TACZ gun ID/display ID 和维度。合法的热量/弹药 NBT 变化不误判为换武器。死亡、实际伤害、换槽/换武器、失去部署资格、退出/切维度都会取消，取消不回血、不扣包、不解除上限。移动、奔跑、跳跃和蹲下没有被医疗锁修改。

`MedicalDamageMixin` 在 `Player.actuallyHurt` 前后比较**实际生命和吸收值损失**，因此最终被取消或零损失的伤害不误中断；吸收值真实减少也会取消。原动态回血上限仍只依据已有最终生命伤害规则收紧，不把吸收损失额外当作生命伤情。

## 5. 枪械与其他战斗入口

实际 TACZ 的 `GunShootEvent` 在扣弹之后，不能作为主要拦截。以下 Mixin 在方法 HEAD 拒绝执行：

| 位置 | 覆盖 |
|---|---|
| `LivingEntityShoot.shoot` | 服务端权威射击、直接/伪造请求，经由实际枪手操作入口，扣弹前返回取消 |
| `LivingEntityReload.reload` | 服务端新换弹 |
| `LivingEntityAim.aim(true)` | 服务端 ADS；允许 `aim(false)` 正常退出 |
| `LivingEntityMelee.melee` | 服务端枪托/枪口近战 |
| `ModernKineticGunScriptAPI.shootOnce` | 延迟脚本/连发射击的额外扣弹前防线 |
| `LocalPlayerShoot.shoot`、实际 burst/排队回调 | 客户端单发、全自动、连发后续任务、排队后坐力/声音；1.1.8 蓄力临时输入状态也清理 |
| `LocalPlayerReload`、`LocalPlayerAim`、`LocalPlayerMelee` | 客户端换弹、ADS、枪械近战 |

自疗开始检查 TACZ 权威 holder 的换弹/拉栓状态以及同步状态，避免同 tick 同步尚未更新时误启动；也检查拔枪、近战、正在使用物品、睡眠。不会强行取消已有换弹。另拦截原版攻击、物品使用和方块使用，覆盖近战及原版弓弩/投掷物使用入口。已合法发出的子弹继续存在。管理员命令造成的伤害/轰炸不作为普通武器输入承诺范围。

## 6. 开火释放规则与输入

医疗权威动作、客户端动画、库存、`FireReleaseGate` 分开维护。同步开始后退出 ADS、清理相关按键 click 队列，取消新的射击/使用输入；客户端射击操作和实际排队连发任务也检查同一释放门闩。

结束或取消仅解除医疗动作；原先仍按住开火时，释放门闩继续阻止重新射击。观察实际 TACZ `ShootKey.SHOOT_KEY` 和原版攻击绑定的物理释放后才重新允许射击，支持键鼠重绑定，不硬编码鼠标左键。断线/世界卸载清视觉，释放门闩有独立清理路径。

医疗按键采用 Forge 可重绑定 KeyMapping，并通过键盘/鼠标 **GLFW_PRESS 边沿事件**发送意图，忽略 GLFW_REPEAT；因此短于一个客户端 tick 的点击也不会漏按，按住不会重复发起。打开聊天或菜单时不会发送意图，尊重 Forge 控制上下文和修饰键。

## 7. HUD 与第一人称

血条、生命数字、医疗指示器作为整体按 GUI 宽度居中。数字使用为最大生命值预留的文字宽度，右侧等臂像素医疗十字和 0/1 保持可见；无限使用图形绘制的小型 ∞，不依赖字体。医疗指示器仅读服务端状态，不推断库存。非战斗、死亡、旁观、等待有效部署时按显示条件隐藏。

第一人称使用 `RenderHandEvent` 高优先级取消两只原有手/枪，只在主手 pass 绘制一次玩家皮肤手臂及共享医疗包模型，按玩家主手左右镜像。平滑进入 → 停留 → 收回；不修改实际物品、快捷栏或枪械 NBT。PoseStack 用 try/finally 配对还原。第三人称不画第一人称模型，不取消服务端治疗；开界面隐藏视觉，动作仍由服务端结束/取消。客户端 Mixin 和渲染类严格放在 client 配置/Dist.CLIENT 侧。

## 8. 投递

J 仅发送分发意图。服务端从真实眼位和视线筛选同战局、同队、同维度、存活已部署、普通兵种且库存 0 的队友；不选择自己、身后、敌人、医疗兵或库存 1 的目标，满血空库存队友可以接收。按准星接近程度、距离、UUID 稳定排序，并检查发射点及接收区域的初始碰撞视线。

同一医疗兵最多一枚在途，只有 `addFreshEntity` 成功才启动冷却。无目标或被拒绝不计成功发射冷却；成功后撞墙/失效不退款。普通请求另有 4 tick 网络节流。

实体服务端有限转向、恒速追踪指定目标，不寻路、不改投。每一步检查上一位置到下一位置的完整线段，使用真实方块 COLLIDER 形状；比较目标 AABB 与墙体的最近交点，墙先则销毁。其他玩家不截获。收到时再次复核双方角色/队伍/战局/维度、原部署生命和目标库存，只执行一次 0→1 和同步，**不治疗、不解除上限**。两枚竞争最多一枚成功。

死亡、重部署、离局、换队、退出/切维度、目标库存已满、超时、撞墙和身份失效都会销毁。无 ItemEntity、伤害、拾取、落地停留、漏斗功能。EntityType.noSave + shouldBeSaved=false；异常恢复 readAdditionalSaveData 也直接 discard。访问轨迹前检查所涉区块已加载，不创建区块票据或强制加载。

## 9. 同步与协议

协议升至 6：旧网络消息编号保持原位，新医疗意图/状态包追加末尾；部署请求增加服务端验证的兵种候选。两种医疗包均限定网络方向。C2S 不上传操作者、目标 UUID、库存、治疗量、时间或“治疗完成”，从连接上下文取发送者并 enqueueWork 到主线程，复用 PacketRateLimiter。请求另外携带不可信的生命 UUID 与状态 revision，服务端严格比较当前记录，明确拒绝上一生命、上一动作的迟到意图；这些标识不能授予库存、兵种或治疗效果。

连发取消直接结束 TACZ 当前 ScheduledFuture，避免旧计数器在治疗结束后继续；射击拦截使用不依赖形参排列的 callback-only Mixin，涵盖 1.1.7 单入口与 1.1.8 多重载。

S2C 携带生命 UUID、递增 revision、服务端资格、医疗兵能力、0/1 储备及当前动作 ID/进度。开始、取消、完成、接收、部署、重连、切维度均同步。旧 revision 被忽略，相同动作不会重启动画；TCP 顺序配合世界卸载清理隔离生命切换。专用服务端运行验证未加载客户端渲染类。

## 10. 最终按键与默认配置

自疗 **C**；分发 **J**；既有部署界面 **U**。C 与 TACZ Crawl、原版创造模式 Save Hotbar Activator 共用默认键，保留其他绑定，并在控制名称及进入有效部署后的消息中明确提示重绑。G 是 TACZ 切换射击模式，H 是检视枪械，因此选择空闲的 J 分发，不混用 C。

4. 治疗中受伤、换槽、用其他方式替换武器、死亡/重新部署、退出/换维度/换队，确认立即结束且无消耗/残影。切第三人称只隐藏第一人称展示，不取消服务端动作。
5. 医疗兵瞄准同队空库存普通兵按 J：命中只补库存。用满库存、医疗兵、敌人、墙后、背后目标验证拒绝；失败请求不占成功冷却。
6. 两医疗兵同时投递、目标移动到墙后、穿薄玻璃板、半砖/台阶、目标死亡重部署、发射者退出、实体超时/区块卸载/服务器重启，确认不隔墙/跨生命补给，不生成地面物品。
7. GUI 缩放 1–4、窄窗口、左右主手、枪械与空手分别检查十字与 0/1/∞、皮肤手臂、模型朝向、平滑进出及正常恢复持枪。
