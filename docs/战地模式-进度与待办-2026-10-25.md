## 〇、一句话结论

**核心对局闭环已经跑通并且有实机证据**（加入 → 倒计时 → 传送 → 占点 → 战线推进 → 结算 → 回大厅），
**但"战地"作为玩法还差三块骨头：兵种、武器准入、载具**；另有一批"多局并行/世界实例化"的新代码只过了编译，没过实机。

### 2.2 体验层（✅ 大部分实机验证过）

- **HUD**：计时/票数、菱形据点环（扇形进度，蓝永远代表我方）、小队分、中央飘字、出界警告、阶段遮罩
- **区域可视化**：地面圈 + 可活动矩形白框
- **小队**：自动补齐、4 人上限、面板（`team/ui` 4 个类）、按对局内存分桶

- **火力支援**：区域轰炸（敌我红蓝烟）、V1 贝塞尔弹道

```
#1 防守票数模型 ──┐
                  ├──▶ #9 征服模式
#6 武器准入 ──────┼──▶ #5 兵种体系 ──▶ #12 载具（兵种专属载具/反坦克）
```

优先顺序建议：**#3 → #4 → #2 → #6 → #5 → #8 → #1/#9**。
理由：#3 和 #4 是"现在就可能炸"的风险；#2 是小改动但影响每个玩家的复活体验；#6/#5 是玩法骨架；#8 是留存。

## 五、风险与阻塞点

| 风险 | 影响 | 说明 |
|---|---|---|
| **配装插件是单点依赖** | 玩家空手上场 | `BackpackBridge` 反射失败只返回 false，没有兜底发枪逻辑 |
| **模板世界靠人工准备** | 开局直接失败 | `TemplateStore.templatesDir()/<name>/region` 不存在就拒绝创建对局，运维必须手工铺模板 |
| **槽位沿 X 轴一排** | 地图宽了会串位 | `slotBaseX + k * slotSpacingBlocks`，间距配置小于模板宽度就会重叠 |
| **无对局状态持久化** | 崩服后"在场不在局" | `MATCHES` / `PLAYER_MATCH` 全在内存，重启即丢 |
| **部署 jar 靠人工同步** | 再次分叉 | 服务端 + 客户端 + 可选多个实例，必须同时更新 |
| **新代码缺实机覆盖** | 上线才发现 | 世界槽位、小队面板、包限频都只过了编译（部署界面已补实机） |
| **据点 2D 判定** | 战术深度受限 | 多层建筑里无法做"楼上楼下"的争夺 |

## 六、建议的三个里程碑

**M1「能稳定连打三局」（1~2 天）**
验证 #4 世界槽位 + #3 装备链路兜底 + 槽位还原干净。目标是：同一张图连开三局，第二局进场时地图是干净的、玩家有枪。

**M2「一局像个战地局」（3~5 天）**
#2 部署界面闭环 → #6 武器准入 → #5 兵种体系。目标是：死亡后能选兵种和出生点，武器受白名单约束。

**M3「能开服运营」（3~5 天）**
#8 战绩结算 → #1 票数模型 → #9 征服模式。目标是：打完能看战绩，攻守有对称的胜负条件。
