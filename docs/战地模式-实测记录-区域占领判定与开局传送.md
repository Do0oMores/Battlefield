### ❌ 发现的 Bug

**Bug-1（已修复并实测）：占点/驻点计分几乎永远不会发放**
- 现象：Player1 两局共在 A 点累计站立 ~90 秒（应得 ~150 分），HUD 面板 `总分:0`，全程无 `+N 占领` toast（截图 06/07/08）。
- 根因：`SectorManager.updatePoint` 用 `level.getGameTime() % 60 == 0` 决定是否发分，而占点循环只在 `ctx.tickCounter % 10 == 0` 时运行。两个时钟存在固定偏移 C=startGameTick−tickCounter₀，**仅当 C≡0 (mod 10) 时两者才会相交**，即每局只有 1/10 概率正常发分，其余 90% 的对局该分支一次都不会执行。
- 证据链：占点推进正常（同一循环的计数分支在跑）+ 计分恒为 0 + 无 toast；部署 jar 字节码确认 `addCaptureScore/addDefendScore` 调用存在，排除构建问题。
- 修复（23:23 构建）：
  1. `GameSession` 新增 `nextScoreAwardTick` 与 `isScoreAwardDue()`：用 gameTime 记录"下次到期时刻"，到期即发并顺延一个 `scoreAwardIntervalTicks`，调度与比较同一时钟，彻底摆脱另一个计数器的相位；
  2. `SectorManager.tick` 每次只取一次 `isScoreAwardDue()` 并传给所有据点，保持"同一 tick 内所有据点同时结算"的原语义；
  3. 删除 `updatePoint` 里的 `gameTime % interval == 0` 判断。
- 实测（23:28~23:31，新 jar）：
  - Player1 站 A 点 11 秒 → HUD 面板 **总分:20**（截图 `12-占点计分修复后-12秒.png`），正好是 4 次 ×5 分，节奏=每 3 秒一次，**没有出现每 tick 刷分**（若失效会变成 110+）；
  - A 点照常推进并在约 30 秒后变蓝（截图 `13-占点toast-2.png`），占点逻辑无回归。

**Bug-2（设计缺口）：「按占领点 progress 门控可活动范围」未接线**
- `BattlefieldAreaRules.isPointInMovableRange`（攻方 progress>=0 才可活动）与 `isInsideMovableAreaServer` 是死代码；服务端强制判定只用 sectors.json 的静态矩形。若设计意图是"据点未解锁前攻方不能深入"，该功能目前不存在。另外 `areaRadiusScale=1.6` 只被这段死代码引用，实际不生效。

**Bug-3（已修复并实测）：对局中途加入的玩家收不到区域包，且会被传到等待区**
- 原实现：`sendSectorAreas` 只在 `ensureSession`（开局倒计时）和战线推进时发送；`joinBattle` 一律传送到 `arena.wait`。中途加入者客户端 `attackerAreas/defenderAreas` 为空 → 无白框、无出界警告，但服务端 `enforceMovableArea` 照样计时击杀；若 wait 落在矩形外，开局即被判死。
- 修复（23:12 构建）：
  1. `BattlefieldNet.sendSectorAreasTo(player, ...)` 新增单发接口，`joinBattle` 在对局进行中/倒计时阶段给新加入者补发当前战线区域包；
  2. `joinBattle` 按阶段分流：WAITING 传 wait 区，其他阶段直接落本方主出生点；
  3. ENDING 阶段拒绝加入并回显「正在结算」；
  4. `ClientGameState` 增加 `areasInitialized`，中途加入收到的第一份区域包不再误播「推进至下一战线」语音。
- 实测（23:16~23:20，新 jar）：
  - P2 对局进行中 `bt leave` → 存档坐标回 lobby (18,110,-8)；
  - P2 再次 `bt join area_alpha` → 存档坐标 **(-13,117,-1)=firstDefendSpawnPoint**（不是 wait 的 15,110,-2）✅
  - 客户端出界警告正常出现：截图 `11b-出界警告复测.png` 显示「您正在离开战斗区域 8 秒」+ 暗色遮罩（该警告只在区域包非空时才会渲染，即证明补发到位）✅
  - TP 至 (100,130,0) 后**精确 10 秒**被杀（23:19:20→23:19:30），复活于 (-13,117,-1)、血量 20 ✅
- 未覆盖：倒计时阶段加入（同一代码分支，仅代码审查）、ENDING 拒绝加入（需精确卡 10 秒结算窗口，未实测）。

### ⚠️ 本轮测试的干扰项（非模组 bug）
- 区域轰炸两次均未对 Player2 造成伤害：落点用 `MOTION_BLOCKING_NO_LEAVES` 高度图，林区取到树冠下方地面，爆炸中心到站在 y=117 的玩家眼睛距离 > 3（伤害半径），判定全 miss。Player2 存档里 4.33 血是上轮会话残留。**轰炸计分链路（onBombDamage→addScore）本轮未能实测**，但该路径不走 gameTime 取模，不受 Bug-1 影响。
- Player1 首次进服掉线一次（客户端 authlib HTTP 超时，环境问题），重启客户端后正常。
- 加分 toast 在测试窗口分辨率下不可见：HUD 用 GUI 缩放后的 screenHeight/2+140 定位，窗口较小时会落到屏幕外——这是既有布局问题，与计分逻辑无关，小窗口/高 GUI 缩放时值得单独修。
